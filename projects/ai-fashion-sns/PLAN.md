# 新規事業案: AIファッション自動投稿サービス

`/task-discussion` による部門横断議論（CEO/Research/Dev/Marketing）を経て、CEO（ユーザー）が方向性を確定した内容を記録する。

## 確定フロー（毎朝実行・MVP版）

1. トレンド取得（無料のWeb検索ベースで近似取得）
2. 流行りの服装を取得
3. プロンプト生成
4. 画像生成 20枚
5. Claude が採点
6. 上位5枚だけ残す
7. Googleドライブへ保存 ★自動化範囲はここまで
8. （X投稿はCEO本人が手動で行う）
9. いいね数取得
10. 学習
11. 翌日は改善

※ 動画化ステップはいったんスコープ外（フェーズ2で検討）。まずは画像＋Driveまでで運用を検証する。

## 各AI・APIの役割分担

| 担当 | 役割 |
|---|---|
| Claude | トレンド情報の要約・画像生成用プロンプトの作成、20枚の採点・上位5枚選定、投稿後の反応分析と翌日への改善提案（司令塔＋学習ループ担当）。ChatGPTの役割はここに統合し、ChatGPTは使わない |
| Gemini（Google API） | プロンプトから画像を試作・生成 |
| Grok（xAI API） | 構図・ポーズ違いのバリエーションを大量生成（1日20枚分） |
| 画像補正API（Stability AI / Photoroom 等、Meitu代替） | 選ばれた5枚の補正・高品質化 |
| Googleドライブ API | 完成した画像を指定フォルダへ自動保存 |

※ Claudeは画像そのものは生成できないため、画像生成はGemini/Grokが担当する。

## 確定した方針・ガードレール

- **人物**: バズっている画像の構図・ポーズは参考にするが、人物自体は完全オリジナルの日本人を生成する。実在人物のコピー・なりすましは行わない（肖像権・炎上リスク対策）。
- **服のロゴ・柄**: ロゴは無地でOK、生地は似たものでOK。実在ブランドのロゴ・特徴的な柄をそのまま複製はしない（商標権リスク対策）。
- **投稿**: 自動化範囲はGoogleドライブへの保存まで。X（旧Twitter）への投稿はCEO本人が手動で行う（アカウント運用・BANリスクの管理を本人がコントロール）。
- **トレンド取得**: 最初は無料のWeb検索ベースの近似取得で開始する。X公式APIの精度が必要になった段階で有料プランへの切り替えを検討する。
- **動画化**: 最初のMVPではやらない。画像＋Drive保存までで運用を検証してから追加を検討する。
- **人手ゲート**: 投稿前の人手レビューは必須ではなく任意のオプション。最初は入れておき、運用が安定したら段階的に外す想定。
- **学習指標**: 「いいね数」単独ではなく、保存数・CTR等も併用する（釣り的コンテンツ化の回避）。

## 技術メモ（Dev部門の議論より）

- Gemini / Grok はいずれも公式APIで自動化可能。
- Meitu はモバイルアプリの操作自動化ではなく、API経由の代替ツール（Cloudinary, Photoroom, Stability AI 等）に置き換える。
- トレンド取得は当面、一般的なWeb検索（ニュース・トレンドまとめ記事等）による近似で行う。X上の実データではないため精度・鮮度は劣るが、まずコストをかけずに検証する。
- 最終出力はGoogle Drive APIで指定フォルダにアップロードするところまでを自動化範囲とする（X投稿・動画化は対象外）。
- いいね数取得・学習ループは、X投稿後にCEOが手動で数値を確認する運用か、X APIの読み取りのみ利用して反応を取得するかは別途検討。
- MVPはプロンプト生成→画像生成→Claude採点→Driveアップロードを疎結合につないで通しで動かす、最小構成から始める。
- 失敗時のフォールバック（リトライ・前日データ流用）とエラー通知、日次コスト上限のアラートを用意する。

## 未確定・要判断事項

- **予算上限**: 画像20枚を毎日生成する場合のAPIコスト上限が未確定。初期は生成枚数を絞って実コストを計測してから決定する案あり。
- **いいね数の取得方法**: X投稿は手動のため、反応データ（いいね数等）をどう自動取得するか（X API読み取り連携 or 手動入力）を決める必要あり。
