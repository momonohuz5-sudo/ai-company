# 新規事業案: AIファッション自動投稿サービス

`/task-discussion` による部門横断議論（CEO/Research/Dev/Marketing）を経て、CEO（ユーザー）が方向性を確定した内容を記録する。

## 確定フロー（毎朝実行）

1. トレンド取得
2. 流行りの服装を取得
3. プロンプト生成
4. 画像生成 20枚
5. Claude が採点
6. 上位5枚だけ残す
7. 動画化
8. 自動投稿
9. いいね数取得
10. 学習
11. 翌日は改善

## 確定した方針・ガードレール

- **人物**: バズっている画像の構図・ポーズは参考にするが、人物自体は完全オリジナルの日本人を生成する。実在人物のコピー・なりすましは行わない（肖像権・炎上リスク対策）。
- **服のロゴ・柄**: 実在ブランドのロゴ・特徴的な柄をそのまま生成しない。ジャンル・色味・シルエットレベルの参考に留め、ロゴは架空または無地にする（商標権リスク対策）。
- **人手ゲート**: 投稿前の人手レビューは必須ではなく任意のオプション。最初は入れておき、運用が安定したら段階的に外す想定。
- **AI生成である旨の開示**: プロフィール・投稿で明記する（プラットフォーム規約・法規制対応、ブランド毀損回避）。
- **学習指標**: 「いいね数」単独ではなく、保存数・CTR等も併用する（釣り的コンテンツ化の回避）。

## 技術メモ（Dev部門の議論より）

- ChatGPT / Gemini / Grok / X はいずれも公式APIで自動化可能。
- Meitu / CapCut / Flow はモバイルアプリの操作自動化ではなく、API経由の代替ツールに置き換える。
  - 画像補正の代替候補: Cloudinary, Photoroom, Stability AI 等のAPI
  - 動画化の代替候補: Runway ML API, Vertex AI 経由の Veo, Shotstack / FFmpeg
- MVPはまず自動化しやすい工程（プロンプト生成→画像生成→Claude採点→X投稿）を疎結合につないで通しで動かし、補正・動画化は後段で強化する。
- 失敗時のフォールバック（リトライ・投稿スキップ・前日データ流用）とエラー通知、日次コスト上限のアラートを用意する。

## 未確定・要判断事項

- **予算上限**: 画像20枚＋動画生成を毎日回す場合のAPIコスト上限が未確定。初期は生成枚数を絞って実コストを計測してから決定する案あり。
- 著作権・商標に関する最終的なガードレール実装（プロンプト側でのブロックリスト等）は今後Dev側で設計する。

## 次のアクション

- **Dev**: 上記MVP方針での技術設計・アーキテクチャ検討、代替API（画像補正/動画化）の選定・検証
