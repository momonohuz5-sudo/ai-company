# タスク議論プロセス

新しいタスクや意思決定事項について、実行に移る前に関連部門の視点から検討する。
すでに部門・進め方が明確なごく単純な作業（誤字修正、1行のバグ修正など）には使わない。

## 手順

1. **議論対象の確認**
   - 引数または直前の会話からタスク内容を特定する。曖昧な場合はユーザーに確認する。

2. **関連部門の選定**
   - `ceo/CLAUDE.md`, `secretary/CLAUDE.md`, `pm/CLAUDE.md`, `research/CLAUDE.md`, `dev/CLAUDE.md`, `marketing/CLAUDE.md` を読み、タスクの内容に関係する部門を2〜4個選ぶ（全部門を毎回巻き込む必要はない）。
   - 迷ったら PM は常に含める（進行・調整役のため）。

3. **各部門の意見を並行して収集**
   - 選定した部門ごとに Agent（subagent_type: claude、general-purpose 等）を1体ずつ立ち上げる。
   - 各エージェントへのプロンプトには次を含める：
     - その部門の `CLAUDE.md` の内容（役割・責務・行動指針）
     - 議論対象のタスク内容と背景
     - 「この部門の立場から、懸念点・推奨アクション・優先すべき論点を述べよ。200字程度で簡潔に」という指示
   - 依存関係がないので、複数の Agent 呼び出しは同一メッセージ内で並列に行う。

4. **論点整理・合意形成**
   - 各部門の意見を集めたら、PM の視点（`pm/CLAUDE.md` の基準）で統合する：
     - 意見が一致している点
     - 対立・トレードオフがある点とその理由
     - 未解決の論点があれば、CEO判断が必要かどうかを明示する
   - 最終的な推奨方針を1つにまとめる。

5. **ユーザーへの提示**
   - 各部門の意見（要約）→ 論点整理 → 推奨方針、の順で簡潔に提示する。
   - 合意形成のみで終わらせず、次のアクション（誰が何をするか）を明確にする。
   - 意見の対立が大きく、CEO判断が必要な場合は、実行前にユーザーに判断を仰ぐ。
